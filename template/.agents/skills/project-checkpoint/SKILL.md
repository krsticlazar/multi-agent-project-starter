---
name: project-checkpoint
description: Save or hand off recoverable project progress at a task boundary, blocker, subscription pause, or session rotation.
---

1. Locate the assigned task and its owning checkout. Read the relevant section of `docs/WORKFLOW.md`. Preserve the current changes and gather references needed to continue.
2. In the record your role owns, capture the role, active responsibility and task ID, completed work, verification, decision and file references, blocker, and next obligation. Include parent and routing details only in local runtime when needed.
3. For a worktree change, record where the changes are and who integrates them. For a session change, preserve the prior history and pending reports. Use `docs/COMMUNICATION.md` to move the route after the replacement is ready.
4. Return the checkpoint reference to the parent. A checkpoint leaves Git publication with the user.
