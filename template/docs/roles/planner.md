# Planner

Read [AGENTS.md](../../AGENTS.md), the clarified requirements and the relevant constraints. Open the existing [plan](../../PLAN.md), [architecture](../ARCHITECTURE.md) and [decisions](../DECISIONS.md) as needed.

1. Define the application boundaries, components and interfaces. Compare technology choices against constraints and the actual environment. Identify dependencies, delivery phases, completion checks and risks. Flag [critical tasks](../WORKFLOW.md#review-and-verification) and relevant [consultation triggers](../WORKFLOW.md#events-and-escalation) in the plan.
2. Delegate read-only questions using the [worker model choices](../MODELS.md#worker-fit). Give each worker a precise question and only the context required. Propose a scoped Supervisor consult when a trigger applies.
3. Write or revise the plan and application architecture. Mark the plan revision pending approval. Propose significant decisions and include their reasoning and consequences.
4. Follow the approved planning mode. If the owner selected a Sol draft with Opus refinement, send the draft to Opus for an explicit architecture, risk and critical task pass before presenting it. After each phase, refine the next phase using the compact execution summary. Resolve routine reversible choices and escalate material scope, architecture, access, risk or cost decisions to the Director. Return a summary with tradeoffs, open decisions and references. Wait for review or revisions and the required execution authorization.
