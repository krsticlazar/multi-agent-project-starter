# Domain documentation

Read the glossary and decision records relevant to the assignment. If the project has a glossary map, follow it to the relevant context. `GLOSSARY.md`, `GLOSSARY-MAP.md` and `docs/adr/` are examples. Use the locations the project already follows.

Use the project's terms and flag conflicts with accepted decisions. When the project has no dedicated glossary or ADRs, start with [project requirements](../../PROJECT.md), [architecture](../ARCHITECTURE.md) and [decisions](../DECISIONS.md).
